# チケットの変更に合わせてフェーズを戻す

チケットの内容が変わったとき（`/flow edit` で編集した、または dev・edit が issue から変更を取り込んだ）に、進行中の run（`docs/flow/<ticket-id>/main.md` があり、`Status` が `done`・`canceled` 以外）のフェーズを戻すかを決める手順。edit と dev が、この手順を読むよう指示する。

## 手順

1. **影響を示す**：変更がどのフェーズの成果に影響するかを具体的に示す。
   - 例：受け入れ条件が変わった → Approach の方針、Plan の commit 分割と「受け入れ条件 → 確かめ方」の対応表を見直す必要がある。
   - 例：背景の言い回しだけが変わった → 影響なし。
2. **戻すフェーズを選んでもらう**：AskUserQuestion で尋ねる。選択肢は、今のフェーズ以前の Research・Approach・Plan から影響に応じて推奨を付けたものと、「戻さない」。
3. **戻す場合**：
   - `bash <scripts>/state.sh set <ticket-id> Status <選んだフェーズ>:in-progress` を実行する（`Updated` も更新される）。
   - セクションは消さない。戻したフェーズのセクションの先頭に、なぜ戻ったのかを 1 行足す（再開したときに分かるように）：
     - edit で編集した場合：`> チケット編集（<YYYY-MM-DD HH:MM>）：<変更点の要約>`
     - issue から取り込んだ場合：`> issue から取り込み（<YYYY-MM-DD HH:MM>）：<変更点の要約>`
   - 後のフェーズのセクションは、そのフェーズをやり直すときに書き直す。
4. ブランチや commit には触らない。run を丸ごと捨ててやり直したい場合は `/flow reset` を案内する。
5. 呼び出し元に戻る：edit から使った場合は、`/flow dev <ticket-id>` で戻したフェーズから再開できることを案内する。dev から使った場合は、案内せずにそのフェーズから続ける。
